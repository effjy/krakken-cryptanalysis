# Krakken-2048 — division-property integral analysis

A self-contained harness that searches the **Krakken-2048** permutation for
**integral / zero-sum distinguishers** using the **bit-based division property**
(conventional two-subset CBDP), modelled as a MILP and solved with **SCIP**.

It is **sound**: every output bit reported *balanced* is a true zero-sum bit of
the permutation over the chosen input cube. The model is conservative (especially
the ARX layer and the inequality S-box model), so it may *miss* some balanced bits
but **never reports a false one**.

---

## Requirements

- A Python venv with **pyscipopt** (SCIP), **numpy**, **scipy** — by default at
  `~/venv`. Override with `make PY=/path/to/python` or `PY=... ./runs.sh ...`.
- A C compiler (`gcc`) for the reference permutation.

## Quick start

```bash
make                 # build libkrakken.so + generate the exact facet S-box model
./runs.sh 1          # round 1, full word:0 cube, all 2048 output bits
./runs.sh validate   # optional: run the correctness gates
```

Run **one round count per invocation**. Output streams to the terminal and is
saved to `runs/round_<N>.log`. This is meant to be launched and **left running**
(see below).

### `runs.sh` arguments

```
./runs.sh <rounds> [cube] [max_bits] [solver_time_limit]
```
| arg | meaning |
|---|---|
| `rounds` | number of Krakken rounds to model (1..8) |
| `cube` | input cube (saturated bits): `word:W` (default `word:0`), `byte:W:B`, `bits:i,j,k`, or `dim:D[:seed]` |
| `max_bits` | test only the first N output bits (`0` = all 2048); use a small value for a quick smoke test |
| `solver_time_limit` | per-bit SCIP cap in seconds (`0` = none) |

A bit that hits the per-bit cap is logged `unknown` and treated **conservatively
as NOT balanced** — so a capped overnight run still produces only sound results.

A **12 GB virtual-memory cap** is applied (override with `MEM_KB=...`).

## How to read the output

```
BALANCED (provable zero-sum): K bits -> [ ... ]
```
- `K = 0` → no integral distinguisher of this kind survives `rounds` rounds for
  this cube (a *negative* result — evidence of integral resistance at that depth).
- `K > 0` → those output bits are **provably balanced** = an integral
  distinguisher on `rounds` rounds.

**The experiment for the paper:** fix a cube, increase `rounds` until `K` drops
to 0. The largest `rounds` with `K > 0` is the integral-distinguisher length.

Cross-check a positive result on a small cube with `--verify-empirical`
(XOR-sums the real permutation; only for cube dim ≤ 22), e.g.:
```bash
PY=~/venv/bin/python python krakken_divprop.py --rounds 2 --cube dim:16:0 \
    --max-bits 64 --use-facets --verify-empirical
```

## Why this version actually solves (the key fix)

The exact **selector** S-box model adds ~2015 binary selector variables *per
S-box* — ~516k binaries/round. With that model SCIP could not resolve a single
output bit (it timed out on every one).

This harness instead uses a **compact inequality S-box model** (`facets.pkl`,
generated by `gen_facets.py`): a set of linear inequalities that characterizes the
S-box's division-property polytope with **zero extra binary variables**. It is
generated by **no-good exclusion cuts** (one per impossible division transition)
greedily merged into a smaller set, and is **EXACT** — verified numerically over
all 65 536 points to keep every valid trail and exclude every impossible one
(same trail table and algebraic degree 7 as the selector model).

Effect: variables drop **937,952 → 422,112**, and round-1 output bits go from
*never finishing* to **solved to optimality** (≈150 s/bit for the hardest case, a
full 64-bit cube; faster on smaller cubes and as balance sets in at higher rounds).
That is why this is meant to be run over long stretches / overnight.

To compare against the old model: `SBOX=selector` is **not** wired here (this
folder is the clean, facet-only reproduction); the selector path lives in the
original `cbdp.CBDP.sbox` if you ever need it.

## What each file is

| file | role |
|---|---|
| `krakken.c`, `krakken.h` | the reference permutation (built into `libkrakken.so`) |
| `sbox_trails.py` | ABYSSAL S-box division trails, derived from its ANF (degree 7) |
| `layers.py` | probes `libkrakken.so`; extracts the exact GF(2) matrices of the linear layers |
| `model.py` | `chi` & `pressure_arx` as gate circuits + round assembly; caches `matrices.pkl` |
| `cbdp.py` | CBDP MILP primitives (COPY / XOR / linear layer / S-box selector + S-box inequality) |
| `gen_facets.py` | generates the compact **exact** inequality S-box model `facets.pkl` |
| `krakken_divprop.py` | the search CLI (called by `runs.sh`) |
| `validate_wiring.py` | checks the `chi`/`ARX` circuits reproduce the C reference bit-for-bit |
| `validate_arx_rule.py` | checks the ARX division rule is sound vs brute force |
| `runs.sh`, `Makefile` | driver and build |

Generated artifacts (rebuilt by `make`): `libkrakken.so`, `facets.pkl`,
`matrices.pkl`. Safe to `make clean`.

## Correctness gates (`./runs.sh validate`)

1. **Wiring** — `chi`/`pressure_arx` circuits reproduce the C reference bit-for-bit.
2. **ARX rule** — the full-adder carry-chain division model is sound vs brute force.
3. **S-box** — the selector model reproduces the ANF-derived trail table (and
   `gen_facets.py` self-checks the inequality model is sound + exact every run).

## Honest limitations

- The search bounds the **chosen cube(s)**; it is not an all-cube proof. A `K = 0`
  result is "no distinguisher of this family at this depth", consistent with the
  rest of the Krakken battery.
- The ARX layer and the inequality S-box model are **sound over-approximations**:
  a distinguisher found *through* them is real; their absence is conservative.
- 2048 bits is large; expect long solve times. Use `max_bits`, smaller cubes, and
  the per-bit `solver_time_limit` to make steady, sound progress over time.
